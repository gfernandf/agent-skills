# Governance External Evidence Checklist

## Purpose
Capture GitHub UI evidence that cannot be fully automated via API, for release governance records.
These external evidence items supplement the automated JSON reports (`github_branch_protection_report.json`, etc.)

## Manual Evidence Collection (Release Governance Closure)

### 1. GitHub Ruleset Configuration - Master Branch
**Location**: Repository → Settings → Rules → Rulesets

**Evidence to capture:**
- [ ] Screenshot: "Rulesets" page showing active rulesets for `master` branch
- [ ] Screenshot: Ruleset rules configured:
  - [ ] "Require a pull request before merging" - enabled
  - [ ] "Require approvals: at least 1" - enabled
  - [ ] "Dismiss stale pull request approvals" - enabled
  - [ ] "Require conversation resolution" - enabled
  - [ ] "Require status checks to pass" - enabled (with list visible)
  - [ ] "Restrict force pushes" - enabled
  - [ ] "Restrict deletions" - enabled
- [ ] Screenshot: Required status checks list visible:
  - [ ] `cognitive-quality-gates` (present in required checks)
  - [ ] `policy-bundle-governance` (present in required checks)
  - [ ] `runtime_canary` (present in required checks)
- [ ] Screenshot: Bypass control settings (minimal, admin-only preferred)

**Storage location in release bundle:**
```
release_bundles/
  ├── pr-preview-<timestamp>/
  │   ├── manifest.json
  │   ├── evidence/
  │   │   └── github_ui_screenshots/
  │   │       ├── ruleset_master_branch.png
  │   │       ├── ruleset_rules_configuration.png
  │   │       ├── ruleset_required_checks.png
  │   │       ├── ruleset_bypass_control.png
  │   │       └── evidence_manifest.json
```

### 2. Legacy Branch Protection Rules (if applicable)
**Location**: Repository → Settings → Branches (if using legacy rules alongside/instead of rulesets)

**Evidence to capture:**
- [ ] Screenshot: Branch protection rule for `master` branch
- [ ] Screenshot: All required status checks configured
- [ ] Screenshot: PR review requirements
- [ ] Screenshot: Force push / deletion restrictions

**Note**: GitHub prefers Rulesets (modern) over legacy Branch Protection. If only Rulesets are in use, this section can be marked N/A.

### 3. Repository Settings - General
**Location**: Repository → Settings → General

**Evidence to capture:**
- [ ] Screenshot: Default branch setting (should be `master`)
- [ ] Screenshot: Repository visibility (should be `public` for release readiness)

### 4. Required Status Checks Consistency
**Location**: `.github/workflows/` (CI jobs)

**Verification steps:**
- [ ] Confirm `docs/required_status_checks.json` lists all three required checks
- [ ] Run local verification script:
  ```bash
  python tooling/verify_required_status_checks_consistency.py
  ```
- [ ] Capture output: pass/fail status for consistency verification
- [ ] Store verification output in evidence package

### 5. Policy Document Alignment
**Location**: `docs/BRANCH_PROTECTION_POLICY.md`

**Verification:**
- [ ] Policy document exists and is up-to-date
- [ ] Policy matches actual GitHub ruleset configuration
- [ ] Document modification date is recent (within release window)

### 6. Release Readiness Gate Evidence
**Location**: Automatically generated in CI

**Automated verification (no manual screenshots needed):**
- [ ] `artifacts/release_readiness_gate_report.json` - generated by CI
- [ ] `artifacts/release_lineage.json` - generated by CI
- [ ] `artifacts/governance_executive_summary.json` - generated by CI

## Evidence Package Structure (release-bundle level)

When building a release bundle, external evidence should be packaged as:

```json
{
  "contract": "release_bundle_v1",
  "bundle_label": "pr-preview",
  "governance_evidence": {
    "automated_reports": {
      "branch_protection": "artifacts/github_branch_protection_report.json",
      "required_status_checks": "artifacts/required_status_checks_consistency_report.json",
      "release_readiness": "artifacts/release_readiness_gate_report.json",
      "release_lineage": "artifacts/release_lineage.json"
    },
    "external_evidence": {
      "ruleset_ui_screenshots": {
        "master_branch_ruleset": "evidence/github_ui_screenshots/ruleset_master_branch.png",
        "rules_configuration": "evidence/github_ui_screenshots/ruleset_rules_configuration.png",
        "required_checks_visible": "evidence/github_ui_screenshots/ruleset_required_checks.png",
        "bypass_control_settings": "evidence/github_ui_screenshots/ruleset_bypass_control.png"
      },
      "policy_document": {
        "branch_protection_policy": "docs/BRANCH_PROTECTION_POLICY.md",
        "policy_last_updated": "2026-06-11"
      },
      "verification_timestamp": "2026-06-11T00:00:00Z"
    }
  }
}
```

## Timing and Release Gates

**When to collect:**
- Before creating a release bundle for production deployment
- Part of release governance closure gate

**Who should verify:**
- Release manager or governance owner
- Independent reviewer (if multi-person approval required)

**Exit criteria for release:**
- All manual evidence captured (or explicitly marked N/A if feature not in use)
- All UI screenshots consistent with actual GitHub configuration
- Automated reports passing (release_readiness_gate_report.json status: "passed")
- Policy documentation up-to-date and aligned with UI settings

---

## Remediation Steps

If evidence collection reveals gaps:

1. **Missing UI settings**: Apply settings via GitHub ruleset configuration
2. **Inconsistent documentation**: Update `docs/BRANCH_PROTECTION_POLICY.md` to match UI
3. **Failed automated verification**: Run `tooling/verify_github_branch_protection.py` locally with admin token:
   ```bash
   GITHUB_TOKEN=<admin_token> python tooling/verify_github_branch_protection.py --report-file artifacts/github_branch_protection_report.json
   ```
4. **Bypass control too broad**: Restrict bypass rules to admin-only via GitHub UI Ruleset settings
